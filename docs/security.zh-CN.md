# 安全模型

RemoteX 处理的是生产服务器、凭据与高权限操作。本文说明凭据如何流动、哪些边界
由插件强制、哪些边界需要部署方自行配置。

## 信任边界

| 边界 | 信任内容 | 不信任内容 |
| --- | --- | --- |
| DBX 宿主 ↔ 插件 | 宿主提供的连接元数据、secret binding、host API | 插件 webview 不能直接读取明文 secret |
| UI ↔ sidecar | 本机 framed JSON-RPC | RPC 参数按不可信输入校验 |
| sidecar ↔ 远端 | 用户确认过的主机密钥 | 远端返回的路径、文件名、终端输出 |
| MCP 客户端 ↔ 工具 | 显式 `connectionId` 或内联凭据 | 未确认的连接名歧义、未确认的危险命令 |

## 凭据

### 存储

- 连接密码、私钥口令与私钥内容由 DBX 宿主的 secret binding 管理。
- Quick Sudo 密码与 OTP 种子由插件 vault 加密后落盘：每个字段独立 AES-256-GCM 加密，AAD 绑定字段名与条目 id，密文不能跨字段移植。
- Vault 的数据密钥默认放在插件数据目录的 `0600` keyfile 中；也可通过 `DBX_SSH_VAULT_STORAGE=keychain` 选择系统 keychain。这是静态加密，不是需要解锁的保险库。
- UI 只提交用户输入，不把 secret 写入浏览器存储、日志或导出文件。
- sidecar 在连接生命周期内持有解密后的凭据，会话关闭后释放。
- OTP 种子文件使用 `0600` 写入（POSIX），先设权限再写内容，避免明文窗口。

### 密码来源

- **Enter in this form**：写入宿主 secret store。
- **Local command**：连接时以当前用户权限执行；stdout 去掉末尾一个换行作为密码。
  该命令的输出不会写日志。请确保命令本身不把密码写到文件或历史。

### 一次性验证码

- TOTP 与键盘交互验证码只用于当次认证，不持久化。
- MCP 的 `ssh_exec_sudo` 可在 sudo 阶段自动生成并输入 TOTP；种子仍来自连接配置或
  Quick Sudo 档案，不进入工具返回值。
- 审计日志不记录验证码。

### 私钥

- 支持 OpenSSH、PEM、PPK。
- 私钥内容优先于路径；粘贴内容保存在宿主 secret store，之后不再显示。
- 选择文件会清空已粘贴内容，避免两份来源并存。
- 解码错误只报告类型与位置，不回显密钥材料。

## 主机校验

- 首次连接未知主机时显示算法与指纹，要求显式确认。
- 确认后写入**插件自己的** known_hosts 文件，不修改系统 `~/.ssh/known_hosts`。
- 已知主机的密钥变化时拒绝连接，并给出旧/新指纹与处理建议。
- 可在设置中查看与移除条目；移除后下次连接重新进入首次确认流程。
- 独立 stdio MCP 模式对未知主机使用 TOFU：首次记录，之后变化仍拒绝。
- 跳板链的每一跳分别校验。

## 只读模式

连接级只读开关会在 sidecar 强制执行，而不是只隐藏 UI：

- SFTP 写操作（上传、删除、重命名、chmod、touch、创建目录/链接、解压）被拒绝。
- 远程命令执行只接受可证明只读的白名单命令（如 `ls`、`cat`、`df`、`ps`、
  `systemctl status`、`journalctl`、`docker ps`）。
- sudo 与提权执行直接拒绝。
- MCP 写类工具被拒绝；只读巡检命令仍可用。
- 命令补全的远端执行也受只读检查。
- 错误文案说明是“只读连接设置”导致，便于区分网络或权限问题。

白名单是允许列表而非拒绝列表：无法证明只读的命令一律不放行。

## 危险命令

命中灾难模式的命令要求显式确认：

- 磁盘格式化、分区表修改、裸设备写入
- 递归删除系统目录
- 关机、重启、停止关键服务
- 数据库 `DROP` 等破坏性语句

MCP 工具通过 `confirmDestructive: true` 表达人工确认；终端与工作台通过确认弹窗表达。
只读连接上直接拒绝，不提供确认入口。

## sudo

- Quick Sudo 档案保存提权方式、凭据来源与命令白名单。
- 可按连接限定允许的命令前缀；命中白名单的命令无需逐次确认。
- 未命中时要求确认或拒绝，取决于档案策略。
- sudo 密码通过 stdin 传入，不出现在命令行参数或进程标题中。
- 只读连接禁止 sudo。

## 审计

- 审计文件为 append-only JSONL，位于插件数据目录。
- 单文件达到 5 MiB 后轮转为 `.1`，保留一代。
- 记录字段包括时间、连接、工具、命令、门禁结果、审批状态、退出结果与输出摘要。
- 审计是“执行了什么”的账本，不是完整终端录像；不要把终端录像与审计混为一谈。
- 可在安全页查看、筛选、清空。

审计不记录：

- 密码、私钥、口令、TOTP 种子
- 完整环境变量
- 文件内容

## 文件与路径

- 上传/下载的本地路径受 MCP 路径约束；独立 stdio 模式下默认只允许显式配置的目录。
- 远程路径按不可信输入处理；下载先写临时文件再原子替换。
- 归档解压使用库自带的路径穿越防护。
- 符号链接操作显式区分“创建链接”和“读写目标”。
- 录制文件与 OTP 文件按敏感数据设置权限；Windows 上依赖用户目录 ACL。

## MCP 权限档

| 设置 | 作用 |
| --- | --- |
| `DBX_SSH_MCP_READ_ONLY=1` | 进程级只读，拒绝所有写工具与提权 |
| `execPermissionMode` | 写操作是否需要人工确认 |
| `connectionScope` | 允许工具访问的连接清单 |
| 连接级只读 | 该连接上的写操作与 sudo 一律拒绝 |
| sudo 命令白名单 | 限定可自动执行的提权命令 |
| 本地路径约束 | 限制 `sftp_upload` / `sftp_download` 的本地路径 |

这些门禁在建立网络连接之前执行；被拒绝的调用不会到达远端。

## 录制与传输历史

- 录制内容是 asciicast v2，包含终端输入与输出，可能含敏感信息。
- 录制目录权限 `0700`，文件权限 `0600`（POSIX）。
- 不采集系统鼠标指针、光标坐标、剪贴板或窗口标题。
- 传输历史只记录方向、文件名、大小、状态与错误，不记录文件内容或凭据。
- 二者都保存在本机，不会自动上传。

## 日志

- 结构性错误写 stderr，由宿主收集。
- 不在日志中输出密码、私钥、TOTP、完整命令环境或文件内容。
- 诊断信息只包含方法名、错误类型、会话 id 等非敏感字段。

## 部署建议

1. 生产连接启用 Known Hosts 严格校验，首次确认时核对指纹。
2. 对只读巡检账号开启连接级只读。
3. 为 sudo 配置命令白名单，避免通用 `ALL`。
4. MCP 使用连接引用而非内联凭据；给 AI 客户端单独的权限档与连接范围。
5. 定期检查审计页与告警；清空审计前先导出需要保留的记录。
6. 将插件数据目录放在受控位置，并限制其他本机用户的访问。
7. 不要把 `.cast`、审计文件或包含主机信息的截图提交到公共仓库。
